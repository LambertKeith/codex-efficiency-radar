# 方案设计记录

## 2026-09-03：`0.5.0` 客户端更新后自动恢复

- 根因：旧 Resident 只读取安装时复制的静态兼容清单；检测到未知 Codex 构建后立即退出，因此仓库后来补充白名单也不会被已安装运行时感知。
- 新行为：Resident 持续驻留，以轻量安装指纹识别客户端变化，仅在变化时重新计算完整哈希；未知构建保持原生选择器且不终止当前进程，每 15 分钟从固定 GitHub HTTPS 地址重新获取审核清单。
- 自动恢复：远端出现与当前平台、版本、官方应用身份、可执行版本及 `app.asar` SHA-256 完全一致的条目后，等待当前原生 Codex 完整退出，再按增强模式启动。
- 安全边界：远端清单只能选择运行时已经实现的两种选择器契约，不能下发代码；Windows AUMID、macOS Bundle ID/Team ID、响应大小与重定向地址均严格校验。
- 失败降级：网络错误、非法 JSON、未知契约、错误签名或不匹配哈希均保留原生模式；最近一次有效清单以原子写入方式缓存，断网不降低既有审核边界。
- 当前实机：Windows package `26.901.1978.0`、app `26.901.20858`、exe `152.0.7977.64`、asar `09C7…83D`，静态包内容继续包含新版选择器契约标记，已加入精确审核条目。

## 2026-09-02：`0.4.2` 紧凑无边框面板

- 展开菜单内容宽度上限由 `760px` 收至 `580px`，数据视口高度收至 `286px`。
- 移除面板、模型组和档位项的表格式边框，以轻底色和间距维持分组层次。
- 默认只显示短模型名、中文档位和“综合 / 工程”双值；隐藏模型 ID、英文档位、样本数、更新时间与规则长说明。
- “优选 / 当前”从文字徽标改为 `★ / ✓`；完整含义保留在悬停提示、`aria-label` 和项目说明中。
- 成功选择后不再常驻状态文案；仅切换中、失败、旧快照或共享缓存时显示必要状态。

## 2026-09-02：`0.4.1` 卡片化与弹层重挂

- 视觉层取消共享列头、空档位占位和横向滚动，改为“模型卡片 + 自带档位标签的组合胶囊”。
- 当前组合使用蓝色轻描边，优选组合使用暖色轻底色；两类状态以独立徽标表达，避免只依赖颜色。
- 注入调度改用微任务，避免窗口失焦时 `requestAnimationFrame` 暂停造成入口迟迟不出现。
- 同时监听原生弹层的 `data-state`、`aria-hidden` 与 `hidden` 属性，兼容复用 DOM 而非重新挂载的旧版/新版选择器。

## 2026-09-02：选择器能力地图与原生组合选择

### 目标

- 修复新版模型选择器中效率入口、展开内容与原生 `ViewTrack` 固定高度/裁剪区域重叠的问题。
- 保留旧版 `data-codex-intelligence-trigger-v1` 与新版 `data-model-picker-view-v2` 两类已审核契约。
- 将强调表格线框的展示改成贴近 Codex 原生菜单的“能力地图”：每个模型是一张独立卡片，推理档位是卡内可点击胶囊。
- 有数据的组合项可点击，并通过 Codex 已有的模型菜单项、推理菜单项或 Power 控件生效；不创建私有配置接口。
- 对相对高性价比组合做文字和视觉双重标记，避免只依赖颜色传达信息。

### 已确认根因

当前新版选择器的两个视图位于固定高度的 `ViewTrack` 内，且轨道使用 `overflow: clip`；旧实现把入口分别追加到 simple / advanced 的内部 `ViewPanel`。React 的原生高度测量不包含后插入节点，导致入口和展开面板不参与外层菜单布局，最终与原生内容重叠或被裁剪。

### 设计方案

1. 新版选择器只创建一个入口，并把它追加到包含 `[data-model-picker-view]` 的最外层 `role="menu"` 底部，作为选择器的兄弟节点；simple / advanced 共用该入口。
2. 旧版仍在经契约证据识别出的模型、推理或根菜单底部创建入口，避免误注入普通“低/中/高”菜单。
3. 展开区域使用 `role="grid"` 的能力地图语义，不再使用强边框表格或共享列头。每个档位在模型卡片内自带名称，通过留白、柔和底色和悬浮状态融入原生菜单。
4. 每个有效组合项是按钮，显示“综合 / 工程”双值。点击后：
   - 新版：通过原生 advanced 模型行与 `data-reasoning-slider` 键盘契约选择；每一步读取原生可访问状态校验结果。
   - 旧版：通过 `data-model-picker-model-row`、`data-model-selected`、`data-reasoning-selected` 与原生触发器完成选择。
   - 任何契约缺失、禁用或结果不匹配均停止并显示失败原因，不猜测内部 API。
5. “优选”规则：以推理档位作为相对成本代理；在每个模型内，找出达到该模型最高“双指标均值”95% 的最低档位。只有该档位低于模型最高可用档位时才标记，避免把单纯最高档误称为高性价比。界面同时显示规则说明。
6. 选择期间锁定能力项并显示状态；成功后由原生选择器完成菜单关闭，失败时保留面板便于重试。

### 验收场景

1. 新版 simple / advanced 轨道切换时，外层菜单底部始终只有一个入口，入口与原生内容不重叠。
2. 旧版三个已识别菜单仍各有且仅有一个底部入口；无选择器上下文的普通菜单不注入。
3. 能力地图档位顺序稳定；缺失数据不占空位，有效数据以带档位名称的按钮显示。
4. 优选组合按 95% 最低档规则标记，标记包含“优选”文本和非颜色提示。
5. 点击新版组合后，原生模型与推理状态都与目标一致；原生控件缺失或目标不可用时给出明确错误。
6. 点击旧版组合后，通过旧版原生模型/推理菜单完成选择；契约不完整时安全失败。
7. 刷新成功、桥接异常、超时、迟到 Promise、重复注入及快照更新行为保持通过。
